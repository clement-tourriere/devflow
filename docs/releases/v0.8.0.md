# devflow v0.8.0

This release makes reusable workspace data and interrupted-operation recovery explicit, and replaces internal command wrappers with native libraries.

## Changes

- Reuse versioned, sealed PostgreSQL baselines independently from the code parent. Workspace generations retain exact data origins and immutable engine images; recreating a name can select fresh data.
- Inspect the resolved workspace plan before creation. Saved plans preserve the selected revision, data origin and path when setup is retried.
- Recover interrupted operations through shared CLI and desktop APIs. Cleanup retains ownership and durable receipts on failure, and cancellation is limited to proven no-effect operations.
- Preserve Git staging and merge state during jj inspection, recover stale jj workspaces natively, and keep existing project hooks intact.
- Confine payload copying to its destination and validate destination inputs before reusing caches. Interrupted copy operations preserve existing data.
- Track each explicit execution separately, verify process ownership, and enforce one controller owner per configuration directory.
- Install the optional proxy companion with `DEVFLOW_INSTALL_PROXY=1`; the standard CLI delegates proxy commands to it. Release assets include both binaries and their checksums.
- Upgrade `h2` to 0.4.16 and `rustls` to 0.23.45, fixing [RUSTSEC-2026-0258](https://rustsec.org/advisories/RUSTSEC-2026-0258.html) and [RUSTSEC-2026-0285](https://rustsec.org/advisories/RUSTSEC-2026-0285.html) found by release CI.

## Migration notes

- Internal Git, jj, Docker, filesystem and ZFS operations use native libraries. Explicit commands, hooks, terminals, managed app processes, sessions and executable providers remain supported.
- The built-in commit/AI-generation wrapper, self-update wrapper, partial workspace sandbox, Pitchfork integration and AI permission merging are retired. Use Git, the installer, your agent harness and the native process runtime as appropriate.
- Broad ignored-file and AI-directory copying is deprecated and disabled by default. Configure explicit payloads and fingerprinted caches.
- Existing unowned resources require explicit adoption. Use the reported `service_key` and exact baseline version rather than reconstructing identities.
- Required hooks must complete before a workspace becomes ready. Inspect operation outcomes and resume incomplete setup before starting dependent work.
- Native jj uses jj-lib 0.45.1. ZFS requires a provisioned pool and the system OpenZFS runtime; devflow does not install kernel modules or provision pools.
